# principalfish.github.io

The GitHub Pages static site for **principalfish.co.uk**, plus the Python data
pipeline behind its UK and US election maps, forecasts and poll trackers.

## Basic commands

Needs Node.js with npm (22+ for the Referdle benchmark), Python 3.10+ and the
`sqlite3` CLI. One-time setup:

```bash
npm ci
cd data && python3 -m venv election_data && ./election_data/bin/pip install -r requirements.txt
```

Run from the repo root:

```bash
./server.sh                                       # build the front end, serve on :8000
npm test                                          # front-end tests (Vitest)
cd data && ./election_data/bin/python server.py   # data console on :5055
cd data && ./run_tests.sh                         # strict mypy, then pytest
```

## Environment variables

The data pipeline reads a `.env` file at the repo root. Create it once, then edit
the paths:

```bash
cp .env_example .env
```

**`.env` beats the shell:** `DATABASE_PATH=/tmp/copy.db ./election_data/bin/python …`
still opens the database named in `.env`. To point a script at another database,
edit `.env`.

| Variable | Default | What it sets |
|-|-|-|
| `DATABASE_PATH` | `/home/philiph/dbs/elections.db` | The live SQLite database; keep it on local disk |
| `SIMULATIONS_PATH` | `/home/philiph/dbs/simulations/westminster-latest.npz` | Latest Westminster Monte Carlo draws |
| `ELECTIONS_ARCHIVE_DIR` | `~/dbs/elections` | Local database backups |
| `ELECTIONS_BACKUP_KEEP` | `30` | How many local backups to keep |
| `NYT_CACHE_DIR` | `/home/philiph/dbs/nyt-cache` | Downloaded NYT results |

Set these two for a single command instead:

```bash
PORT=8001 ./server.sh                                           # serve the site on another port
cd data && CONSOLE_DEBUG=1 ./election_data/bin/python server.py # console reload-on-save and debugger
```

## Sections

### Election maps

UK and US map pages, thin shells over one shared D3 engine. Their data files are
generated by the export; edit only each page's `map-modes-shell.json` by hand.
Details: [UK page](electionmaps/README.md), [US page](uselectionmaps/README.md),
[shared engine](electionmapslogic/README.md).

```bash
./server.sh                  # open /electionmaps/ or /uselectionmaps/
npm run minify:electionmaps  # rebuild the bundles after editing electionmapslogic/
```

### Data

SQLAlchemy models, poll and results importers, election models, the static export
and a local web console, all on one SQLite database. Details:
[data/README.md](data/README.md), which links a page for each topic.

```bash
cd data
./election_data/bin/python server.py                               # console: imports, models, backups
./election_data/bin/python scripts/export_elections.py --dry-run   # show the export plan
./election_data/bin/python scripts/export_elections.py             # write the site's data files
./election_data/bin/python scripts/rebuild_database.py --dry-run   # list the rebuild steps
./election_data/bin/python scripts/backup_db.py                    # back up the database
```

### Referdle solver

Browser solver for Referdle, with a correctness and timing benchmark. Details:
[referdle-solver/README.md](referdle-solver/README.md).

```bash
./server.sh                              # open /referdle-solver/
npm run benchmark:referdle -- --record   # fresh checkout: record the local baseline first
npm run benchmark:referdle               # verify against that baseline
```

### Route weather

Import a GPX and see the forecast along the route at each point's arrival time and
altitude. Runs entirely in the browser. Details:
[routeweather/README.md](routeweather/README.md).

```bash
./server.sh   # open /routeweather/
npm test      # includes the route weather specs
```

### Guess the year

"Guess the year" game in `guesstheyear/`: a static front end plus Python helpers
(`app.py`, `wiki.py`, `export.py`).

```bash
cd guesstheyear && ../data/election_data/bin/python export.py   # regenerate challenges.json
```

### Shared site, bio and landing page

`index.html`, `404.html` and `CNAME` are the landing page, error page and custom
domain. `bio/` is a static bio page and `imgs/` holds shared images. `site/` holds
the shared styles, top bar and vendored libraries, and `package.json` the build
tooling (esbuild, terser, clean-css) and Vitest. Details:
[site/README.md](site/README.md).

```bash
npm run vendor:d3   # rebuild the vendored d3 bundle (server.sh also does this)
```
